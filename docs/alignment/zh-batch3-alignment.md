## B3-1 · 直視正義威儀！ 的效力條件從句

### 裁決前分析（保留供稽核）

```
[提報時標記：missing · prose-issue:medium]
ability.censor.behold-the-face-of-justice / tiers[].text

  舊譯    `氣場 < 弱`，目標 2 格內的每個敵人都會對你陷入畏縮（豁免解除）

  正典    text:    "3 + M holy damage; if the target has this potency,
                    each enemy within 2 squares of them is frightened of you (save ends)"
          potency: { characteristic: "presence", level: "weak" }

  提報理由 這一條與「惡徒止步！」結構不同：惡徒止步！的效力是無條件附加，
          剝掉記號後語意完整；本條原文是 “if the target has this potency, …”，
          是條件從句。當時判斷剝掉記號後中文會讀成無條件發生，屬擴大規則範圍。

  當時建議 3 + `力量`神聖傷害，若目標具有此效力，目標 2 格內的每個敵人
          都會對你陷入畏縮（豁免解除）
```

### ✅ 擁有者裁決（2026-07-29）→ **TI-27**

**沿用舊譯，不補寫條件句。**

擁有者裁定：原文的 `if the target has X < potency` 屬**重複描述**——
效力記號 `X < potency` 本身就表示「若目標未通過該效力」，
中文省略重複句**不代表效果變成無條件**。

因此本項**不再列為 `missing`，也不是阻擋批准的 prose-issue**，
改記為**擁有者批准的結構化省略**，對齊狀態歸 **`acceptable`**——
內容等價但字面不同，不是逐字對應，故不能算 `exact`（指南 §8.1）。階層文字維持：

```
3 + `力量`神聖傷害，目標 2 格內的每個敵人都會對你陷入畏縮（豁免解除）
```

其餘兩階層同樣處理。

> ⚠️ **renderer 的義務（裁決的前提）**：
> 必須把結構化的 `potency` 與該階層的**後續效果一起呈現**，
> 讓讀者清楚知道畏縮效果受效力條件控制。
> 若 renderer 做不到，本裁決的前提就不成立，須回頭重議。已寫入 TI-27。

## B3-2 · 審判的 `for that creature`

### 裁決前分析（保留供稽核）

```
[提報時標記：missing · prose-issue:medium]
ability.censor.judgment / followUpActions[0].options[2]

  舊譯    當 1 個被你審判且位於你 10 格內的生物發動具有效力的招式時，
          若該招式只指定 1 個生物，該招式的效力會減少 1 點。

  原文    When a creature judged by you within 10 squares uses an ability with
          a potency that targets only one creature, the potency is reduced by 1

  提報理由 (1) 限定語 `for that creature` 未譯出；

              依 §7.1(4)「不得把模糊處寫得比原文確定」，當時不由 AI 選定。

  當時建議 (a) 補限定語、維持舊譯的修飾讀法
          (b) 改採修飾 potency 的讀法
          (c) 維持舊譯不動

### ✅ 擁有者裁決（2026-07-29）→ **TI-26**

**採建議 (a)。** 維持舊譯對修飾對象的理解，補回 `for that creature`。
**這是擁有者對原文讀法的正式裁決，歧義就此定案，日後不再重開。**

定稿：

```
當 1 個被你審判且位於你 10 格內的生物發動具有效力的招式時，

## V-B3-1 · 三個欄位的結構驗證（**本輪已完成**）

### 問題

`trigger`、`extraCosts`、`followUpActions` 進入中文層時，
`scripts/verify-zh-structure.mjs` **完全不檢查**。
這已是第三次發現「正典有、中文整段缺漏但驗證靜默通過」的同類問題
（`effect` 第一批修、`flavor` 第二批修）。

### ✅ 已實作（2026-07-29）

`scripts/verify-zh-structure.mjs` 新增最小結構驗證，全部**直接比數量**，
不寫成 `c.length && z.length && …`（那樣中文完全缺漏時會短路，等於檢查不存在）：

```
正典有非空 trigger          → 中文必須有非空 trigger
正典有 N 個 extraCosts      → 中文數量必須一致
每個 extraCosts[].effect    → 必須非空
正典有 N 個 followUpActions → 中文數量必須一致
每組 options 數量           → 必須一致
每個 option                 → 必須非空       ← 二次修訂補
正典有 lead／constraint     → 中文對應欄位必須非空
正典有 N 段 effect          → 中文每一段都必須非空  ← 二次修訂補
所有陣列欄位                → Array.isArray()  ← 三次修訂補
```

**這一節分三次才補完，每一次都是同一個盲點的不同層：**

| 修訂 | 補的洞 | 沒補之前會怎樣 |
|---|---|---|
| 一次 | 數量 | 整段漏譯靜默通過 |
| 二次 | 每個元素非空 | 「段落在、內容是空字串」靜默通過 |
| **三次** | **型別是不是陣列** | **`effect: "x"` 靜默通過** |

第三層是外部 review 抓到的，值得記住為什麼會漏：
**字串同樣有 `.length` 與數字索引。** `effect: "x"` 會冒充成「1 段、內容是 x」——
長度對得上、元素也是非空字串，前兩層檢查**全部通過**。
`options: "abc"` 同理，會冒充成 3 個非空選項。
已對 `sections`／`blocks`／`powerRoll.tiers`／`effect`／`extraCosts`／
`followUpActions`／`options`／condition 的 `text` **共 8 處**加上 `Array.isArray()`。
